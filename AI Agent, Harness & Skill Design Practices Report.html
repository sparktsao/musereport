00 / THESIS

真正的設計單位，不再是 prompt

2025–2026 的主流方向已收斂：以 deterministic harness 包住 probabilistic model。模型負責判斷與生成；harness 負責狀態、邊界、資源、驗證與停止。

→

核心結論
高可靠 agent 不是「更長的 system prompt」，而是更好的控制平面：最小化上下文、目的導向工具、可回復狀態、明確 stop policy、獨立 verifier，以及預設隔離的 execution plane。

20step cap 例

Vercel AI SDK 的文件預設；應與完成訊號、finish reason 並用，而非單獨依賴。[VERCEL]

25ktokens / tool result

Claude Code 單一工具回應上限的研究記錄；超限訊息應指向 filter / pagination。[ANTHROPIC]

~100metadata tokens / skill

Agent Skills progressive disclosure 的目標量級；完整內容只在 activation 後載入。[SKILLS SPEC]

01 / AGENT

Agent loop：簡單、可界定、可重啟

先 workflow，後 agent

若 prompt chaining、routing、parallelization 或 orchestrator–worker 已能解題，就不要升級為全自主 loop。只有動態規劃確實帶來可量測增益時，才增加自主度。 [ANTHROPIC · 2024-12]

Plan 是 artifact，不是腦內狀態

把 research / planning 與 execution 分開；將 todo、feature list、handoff、progress 寫入可檢查檔案。計畫腐化時整份重建，通常比局部修補可靠。 [DEEP AGENTS] [RALPH]

停止條件必須是組合式

同時使用硬性 step / time / token budget、模型 finish reason、可機器驗證的 acceptance test，以及必要時的 completion sentinel。不要讓「模型覺得完成」成為唯一出口。

工作者不替自己打分

讓 fresh reviewer 或不同 agent 檢查軌跡與最終狀態。Verifier 應有較少的 mutation 權限，且其 rubric 本身也要被校準。 [ANTHROPIC EVALS]

長任務靠磁碟交棒

用 progress file、JSON feature list、git history 與結構化 handoff 跨 context reset 恢復。新的 session 先讀現況、跑測試，再接手單一增量。 [HARNESS · LIVE VERIFIED]

多 agent 的首要價值是 context isolation

重探索、專業工具或高雜訊任務交給 subagent；回主 agent 時只帶結構化摘要。多 agent 的代價很高：Anthropic 的研究系統資料稱約為一般聊天 token 的 15 倍，因此要依任務可平行性刻意路由。 [MULTI-AGENT · VENDOR REPORT]

推薦的 bounded loop DETERMINISTIC OUTSIDE · JUDGMENT INSIDE
1 · Observe + Retrieve只拉本回合所需檔案、記憶與工具；將外部內容標示為不可信資料。
→
2 · Decide + Act模型產生單一下一步；harness 驗證 schema、權限與資源。
→
3 · Verify + Continue?測試環境狀態；若不符合任何 stop condition，回到 Observe。

停止策略：至少四層

HARD BUDGETiterations · wall time · tokens · cost

防止失控，不代表任務成功；超限時回傳 partial state 與 resume point。

MODEL SIGNALfinish_reason · no tool call · sentinel

適合做候選完成訊號，但不能單獨作為 acceptance。

ENVIRONMENTtests · typecheck · final DB state

以外部可觀測狀態判定，不只看自然語言答案。

VERIFIERfresh reviewer · rubric · passk

將 reviewer 與 executor 分離；對高風險任務加入 human gate。

Context、memory、retrieval 與 prompt：同一條資料管線

Context 是 projection，不是 history dump

完整 event log 留在 harness；每回合只把目標、最新觀察、必要決策、可用工具與少量證據投影進 model window。Token 越多不等於記得越多；研究資料稱長 context 的 recall 會逐漸腐化。 [CONTEXT ENGINEERING · 2025-09]

Compaction 先清 tool result，再做摘要

先刪除可重新取得的冗長工具輸出；接近上限時再摘要。摘要調校採 recall-first：優先保留架構決策、未解 bug、驗證結果、下一步與關鍵 implementation detail，再慢慢提高 precision。

Memory 分層，並依 query route

短期 episodic buffer 保持回合連貫；semantic / vector store 找模糊相關事實；graph 處理 entity relationship；磁碟上的 progress、git 與 handoff 承擔 durable state。混合記憶的優勢在研究資料中僅有次級來源支持，應以自己的 eval 驗證。

File 與 web retrieval 都要先縮小、後閱讀

檔案先用路徑、symbol、grep 或 head / tail 找候選，再精讀小區段；web / MCP 先 filter、paginate、去重與抽取高訊號欄位，不把整頁、全部 schema 或中間結果灌進 window。外部文字一律視為 data，而非 instruction。

Prompt template 採 stable prefix 分層

順序建議為 base identity → policy / tool guidance → project conventions（如 AGENTS.md）→ session handoff → turn-scoped objective。把穩定內容放前面、易變內容放後面，才能維持 prompt cache 命中；per-turn nudges 不應污染長期規則。

STABLE PREFIX
Identity · policy · tool contracts

低頻變動；適合 prompt caching。序列化順序必須 deterministic。

PROJECT LAYER
Conventions · active skill · durable handoff

依 repository / task 載入；skills 使用 progressive disclosure。

TURN LAYER
Objective · retrieved evidence · latest results

高頻變動；只保留完成下一個 bounded action 所需內容。

COMPACTION
Clear → summarize → externalize

先移除可重取工具輸出，再摘要；重要狀態寫入磁碟或 event log。

02 / HARNESS

Harness：讓 loop 有骨架，也有煞車

Harness 是模型之外的一切：session、tool dispatch、streaming、edit pipeline、workspace isolation、subagent lifecycle 與 stop condition。核心原則是控制與執行分離。

控制平面保持小而 deterministic

state machine、routing、validation、retry budget、stop policy 放在程式碼；模型只在需要 judgment 的 junction 被呼叫。外部 I/O 進 execution plane。

用 hook / middleware 執行不可妥協的規則

PreToolUse、PostToolUse、PreCompact、Stop 等攔截點可阻止寫入敏感檔、在編輯後 lint、在 session start 注入狀態。這是 enforcement layer，不應只寫在 prompt 裡。 [CLAUDE CODE] [DEEP AGENTS]

把 session 當 event log

工具請求、結果、approval、compaction 與 handoff 都應成為可追蹤事件。這支援 crash recovery、debug、trajectory eval 與後續 audit。

Provider、UI、agent core 解耦

Pi 的研究案例將多 provider API、核心 loop、TUI、coding agent 分層；模型與介面可替換，核心只保留最小 tool contract 與 event stream。 [PI · SECONDARY DEEP-DIVES]

Subagent 出去帶少量 context，回來帶摘要

每個 subagent 有自己的 system prompt、工具集合與 context；回傳 JSON 或明確 handoff schema。驗證輸出後再合併，並設定 TTL / depth cap 避免互叫不止。

整個 coding CLI 也能被包成 agent

2026 出現 meta-harness：從 TypeScript 驅動 OpenCode、Claude Code、Codex 或 Pi，並把它們放進 sandbox。這讓「harness wrapping harness」成為編排單位，但權限邊界也必須跟著上移。 [VERCEL · SECONDARY]

// Harness owns the loop; the model proposes one bounded action.
while (budget.ok() && !state.terminal) {
  context = projectHighSignalContext(eventLog, retrieval);
  proposal = await model.decide(context, discoveredTools);
  decision = policy.validate(proposal, capability, target);
  if (decision.needsApproval) await gate.pause(decision);
  result = await sandbox.execute(decision);
  eventLog.append(result);
  state = verifier.evaluate(result, acceptance);
}
不要把 approval 誤認成 containment

「問過使用者」只是一個 decision point。真正的 containment 仍需要 throwaway workspace、唯讀 mount、無 secrets、egress allowlist、CPU / memory / PID / wall-time 限制。

03 / SKILLS

Skill 不是 tool；它是可觸發的作業知識

Agent Skills 把 workflow 封裝成目錄：必要的 SKILL.md 加上可選的 scripts/、references/ 與 assets/。最重要的機制是 progressive disclosure。

Progressive disclosure LOAD ONLY WHAT EARNS ITS TOKENS
L1 · Metadataname + description；啟動時載入，約 100 tokens。Description 是 trigger surface。
→
L2 · SKILL.md相關時才啟用；建議少於 500 行 / 5,000 tokens。
→
L3 · Resourcesscripts、references、assets；只在工作需要時讀取或執行。

Description 要寫成 trigger，不是摘要

明確寫「做什麼」與「何時使用」，包含使用者實際會說的關鍵字。研究記錄指出 skill 常見問題是 under-trigger，而非 over-trigger。 [AGENT SKILLS]

先用 eval 找缺口，再寫 skill

在代表性任務上觀察 agent 失敗軌跡；只把可重用的成功方法、必要 gotchas 與缺失 context 編進 skill。不要從空白抽象地寫一大套規範。

重複性行為寫 code，判斷性行為寫 prose

同一段指令若總是在要求相同轉換，就移入 scripts/；需要情境判斷的流程則保留為說明。清楚標示 script 是要「執行」還是只供「閱讀」。

主檔只放導航與必要規則

將互斥或高細節 context 分拆到 references/，讓模型按需讀取；SKILL.md 建議少於 500 行。 [SPEC · 2025-12]

A/B 測試 trigger 與結果

同一任務跑「有 skill / 無 skill」；Grader 檢查證據、Comparator 盲比、Analyzer 解釋勝因。若 skill 沒載入，先修 description，再懷疑模型。

像 package 一樣治理 skill

審查 SKILL.md 與所有 scripts / assets 的網路、檔案與 shell 行為；維護來源、hash / lockfile、版本與審核紀錄。allowed-tools 是提示，不是 sandbox 或伺服器端授權。 [SUPPLY CHAIN · SECONDARY]

選哪個 primitive？先問「困難在哪裡」

Primitive它擁有什麼適用情境載入時機
Skill作業知識、流程、prose + scripts難點是「知道怎麼做」相關時啟用
Tool / MCP具型別的外部能力與 contract難點是安全接觸變動資料或另一 trust domain通常 session 起始；可 deferred
Hookdeterministic enforcement不可委託模型遵守的 invariant事件發生即執行
Subagent獨立 loop、context、tools隔離重探索或專業工作按需 spawn
Skill + MCP 是互補，不是二選一

Skill 讓 agent 知道怎麼完成流程；MCP server 讓外部整合可治理。不要為靜態知識架 MCP，把精簡材料隨 skill 版本化即可。

04 / CONTROL

安全與評測：看軌跡，也看環境

依 consequence 分 tool tier

Tier 0 可安全讀取；Tier 1 需 review；Tier 2 涉及網路、shell pipeline、credentials 或 production mutation。Approval 應綁 capability + target + invocation，不綁自然語言承諾。

Prompt injection 是架構問題

Repo、retrieved docs、第三方 tool descriptions 都當不可信資料。優先使用 control / data-flow 分離、privileged / quarantined model、最小 capability 與 egress 控制，而非只加一句「忽略惡意指令」。

工具錯誤要能引導下一步

回覆可操作錯誤：錯的是哪個欄位、需要什麼格式、下一個建議 tool 是什麼；避免 stack trace。對 retryable / terminal failure 做明確分類，並設 retry budget。

工具少、用途清楚、結果可裁切

合併成 purpose-built tool，使用 namespace；提供 pagination / filter / concise response。回傳自然語義欄位，不要讓 UUID 與 verbose metadata 消耗推理預算。 [WRITING TOOLS · 2025-09]

評估完整 trajectory + final state

同時量 accuracy、runtime、tool calls、tokens、errors，以及最終檔案 / DB / 測試狀態。單次成功會高估可靠性；production 應看 passk 與失敗分佈。

逐一移除 harness component 做 load-bearing eval

拿掉 compaction、retrieval、reviewer、hook 或某個 tool，再比較 held-out tasks。只有能改善軌跡或環境結果的元件，才值得增加複雜度。

05 / DELTA

2026 相比 2025，改變了什麼

2025
從 prompt engineering 轉向 context engineering

重點變成選哪些 tokens 進 window、如何 compaction，以及如何把高雜訊 I/O 留在 window 外。

2025 Q4
Agent Skills 由內部慣例走向 open spec

SKILL.md 與 progressive disclosure 形成跨工具的工作流封裝介面。

2026
Framework 收斂到 hook / middleware

Deep Agents、Claude Code、Pi extensions、OpenAI guardrail hooks 以 deterministic interception 包住 probabilistic loop。

2026
Skill 成為供應鏈

議題從「怎麼寫」升級為 provenance、scanning、versioning、lockfile、least privilege 與 cross-registry governance。

2026
評測從 final answer 升級為 trajectory

environment-state、harness-component、passk、contamination-free 與 long-horizon benchmarks 變得更重要。

06 / BLUEPRINT

一個可落地的 production blueprint

若今天重做一個 coding / research agent，以下順序比先挑框架更重要。

01
定義 acceptance state

先寫可機器檢查的完成條件，再設 loop。

02
固定 stop policy

step、time、token、cost、finish reason、verifier 一起設。

03
Event log + resume

每一步可追蹤；中斷後能從磁碟重建。

04
JIT context

預載最小 stable prefix，其餘 retrieval、tool、skill 按需進場。

05
Purpose-built tools

數量少、schema 清楚、結果可 filter / paginate、錯誤可行動。

06
Hook enforcement

權限、schema、敏感路徑、lint、approval 不只靠 prompt。

07
Sandbox execution

throwaway clone、無 secrets、read-only mount、egress deny-by-default。

08
Skill A/B + provenance

測 trigger、對 baseline；釘住來源與 hash，審查所有 scripts。

09
Independent verifier

executor 不自評；用 fresh context 檢查 trajectory 與 final state。

10
Held-out harness eval

移除元件做 ablation，只保留真正 load-bearing 的設計。
