01

Executive summary執行摘要

Central thesis核心論點

A model's agent performance is jointly determined by model weights, harness behavior, tool environment and evaluation. Post-training inside the actual harness may improve task success and efficiency; a proxy makes the model calls visible to the trainer.Agent 表現不只取決於模型權重，也受 Harness、工具環境與評估方式影響。在實際 Harness 內做後訓練，可能改善任務成功率與效率；Capture Proxy 則讓訓練器看得到 Harness 發出的模型呼叫。

Reported result演講數據

The talk reports 42% → 54% correctness on held-out data-analysis tasks for a four-harness training setup versus an OpenCode-only run, with fewer tool calls. This is a reported comparison, not proof that reasoning alone improved.演講紀錄指出，在保留的資料分析任務上，四種 Harness 混合訓練相對於只用 OpenCode 訓練，正確率由 42% 升至 54%，工具呼叫也減少。這是演講報告的比較，不能單獨證明純推理能力提升。

What a harness changesHarness 如何影響結果

Responsibilities主要責任

A harness runs the agent loop, exposes tools, constructs and compacts context, interprets model outputs, manages retries and decides when to stop. These choices alter effective agent capability without changing weights.Harness 負責 Agent Loop、工具介面、Context 建構與壓縮、模型輸出解析、重試及終止條件。即使模型權重相同，這些設計也可能大幅改變實際能力。

03

Post-training recipes後訓練方法

SFT on agent tracesAgent Trace 的 SFT

Record real sessions with prompts, assistant tool calls, tool observations, retries and final answers. Train on assistant outputs only (assistant_only_loss); user and tool messages remain conditioning context. SFT imitates recorded behavior, including mistakes in poor-quality traces.記錄 Prompt、Assistant 工具呼叫、Tool Observation、重試與最後答案。只對 Assistant 輸出計算 Loss（assistant_only_loss），User 與 Tool 訊息只提供 Context。SFT 模仿既有行為，也可能學到劣質 Trace 中的錯誤。

Knowledge distillation知識蒸餾

Token-level distillation uses a teacher's soft probability distribution rather than a single one-hot target. On-policy distillation evaluates student-generated tokens under a teacher. Soft targets contain richer preference information but can transfer teacher errors and uncertainty; high token probability is not the same as correctness.Token-level 蒸餾學習 Teacher 的機率分布，而非單一 One-hot 答案。On-policy Distillation 由 Student 產生 Token，再由 Teacher 評估。Soft Target 資訊較豐富，但也會傳遞 Teacher 的錯誤與不確定性；高 Token 機率不等於正確。

GRPO and verifiable rewardGRPO 與可驗證 Reward

The talk illustrates eight generations per coding task and a reward equal to the fraction of hidden tests passed. RL can optimize outcomes beyond a fixed trace, but final-only rewards introduce credit assignment and reward-hacking risks.演講用每題八次生成、以 Hidden Tests 通過比例作為 Reward 的例子說明 GRPO。RL 能超越模仿固定 Trace，但只有最終 Reward 會面臨 Credit Assignment 與 Reward Hacking 問題。

Training objectives are not interchangeable訓練目標不可混為一談

SFT answers 'what did a demonstrated agent do?'; distillation answers 'what distribution does the teacher prefer?'; RL answers 'which behavior maximizes measured reward?'. A verified successful outcome does not certify every intermediate action as optimal.SFT 問「示範的 Agent 做了什麼？」；蒸餾問「Teacher 偏好什麼分布？」；RL 問「什麼行為能最大化可測量 Reward？」。最終結果通過驗證，不代表每個中間 Action 都是最佳選擇。

OpenEnv and training in an environmentOpenEnv 與環境內訓練

Environment contract環境介面

OpenEnv provides an environment abstraction: reset an isolated sandbox, step through actions and observations, and compute a reward. This enables multi-turn execution and recovery before scoring a completed episode.OpenEnv 提供環境抽象：重設獨立 Sandbox、逐步執行 Action 並取得 Observation，最後計算 Reward。讓模型能在評分前進行多回合操作與錯誤修復。

TRL integrationTRL 整合

TRL provides SFT, distillation and GRPO/async GRPO training. The slide's Python examples are architectural illustrations; exact APIs and versions should be checked before implementation.TRL 提供 SFT、蒸餾、GRPO／Async GRPO 等訓練能力。投影片 Python 程式屬於架構示意，實作前仍需核對 API 與版本。

Capture Proxy: precise roleCapture Proxy 的精確定位

What it is它是什麼

A training-aware model API intermediary between an off-the-shelf agent harness and a served model (for example vLLM). It forwards requests/responses and captures the model interactions the trainer otherwise misses, including harness-initiated calls for naming or compaction.它是位於現成 Agent Harness 與模型服務（例如 vLLM）之間、具備訓練感知能力的 API 中介層。它轉送請求與回應，並捕捉 Trainer 原本看不到的呼叫，包括 Harness 自行發起的命名與 Context Compaction。

What it captures它捕捉什麼

Typically prompts, completions, token IDs, generation logprobs (if the backend exposes them), call ordering and policy/model metadata. Tool execution, environment state and final reward require harness or environment instrumentation and reliable episode linkage.通常包括 Prompt、Completion、Token IDs、生成 Logprobs（前提是 Backend 支援）、呼叫順序、Policy／Model Metadata。Tool Execution、Environment State 與最終 Reward 仍需 Harness／Environment 記錄，並正確關聯 Episode。

What it does not do它不做什麼

It does not inherently branch from a decision point, change trajectories, create counterfactual actions, verify correctness or update weights. Those require rollout orchestration, state checkpoint/replay, verifier and trainer.它本身不會在 Decision Point 分支、修改 Trajectory、創造反事實 Action、驗證正確性或更新權重。這些需要 Rollout Orchestrator、State Checkpoint／Replay、Verifier 與 Trainer。

Difference from LiteLLM and tracing與 LiteLLM／一般 Trace 的差異

It resembles LiteLLM at the network layer, but is built to preserve training-critical token/policy metadata and connect asynchronous rollouts to updates. An existing LiteLLM + OpenTelemetry stack can be extended instead, provided it captures lossless training information.在網路架構上類似 LiteLLM，但更重視訓練所需的 Token／Policy Metadata，以及將非同步 Rollout 連到模型更新。若既有 LiteLLM＋OpenTelemetry 可無損記錄必要資訊，也能擴充使用，不必另設 Proxy。

06

Multi-harness and asynchronous RL多 Harness 與非同步 RL

Why train across harnesses為何跨 Harness 訓練

Different harnesses expose distinct tool schemas, prompts, context layouts and termination behavior. Sampling a harness per episode may improve robustness to these conventions. Test on unseen harnesses to distinguish true transfer from memorized formats.不同 Harness 的 Tool Schema、Prompt、Context 與終止方式各異。每個 Episode 隨機抽取 Harness 可能增加穩健性；但應在完全未見過的 Harness 上測試，才能區分遷移能力與格式記憶。

Why async為何需要非同步

Long-running harness episodes can last hours. Async GRPO allows training to proceed as completed rollouts arrive, rather than waiting for the slowest episode. Policy staleness and rollout-to-weight-version attribution must be managed.長時間 Harness Episode 可能持續數小時。Async GRPO 可隨 Rollout 完成陸續更新，不必等待最慢的任務，但要管理 Policy Staleness 與權重版本對應。

Data quality, evaluation and risks資料品質、評估與風險

Reward hackingReward Hacking

The Q&A described analytics agents answering from memorized knowledge instead of querying live data, and coding tasks leaking answers from repositories. Higher reward can reflect exploitation of the benchmark rather than genuine capability.Q&A 提到資料分析 Agent 不查即時資料、直接憑記憶回答，以及程式任務從 Repository 洩漏答案。Reward 提升可能只是利用 Benchmark 漏洞，而非真正能力改善。

Trace quality gateTrace 品質閘門

For SFT, use task-level verification, schema validation, provenance and sampling reviews before accepting traces. The audience proposed scoring traces with a verifiable reward, keeping successful ones, then SFT; the speaker agreed this is a common synthetic-data-loop pattern.SFT 前應進行任務驗證、Schema 檢查、來源追蹤與抽樣審查。現場有人提出先用可驗證 Reward 評分、保留合格 Trace 再 SFT，講者認同這是常見 Synthetic Data Loop。

Evaluation guardrails評估防護

Keep a held-out task set, compare equal inference/training budgets, report success, tool calls, latency, cost and failure modes; audit for data leakage and shortcut solutions. The notes do not provide sample sizes, uncertainty intervals or complete reward definitions.使用獨立測試集、相同推論／訓練預算，比較成功率、工具呼叫、延遲、成本與失敗模式，並稽核資料洩漏及捷徑行為。現有紀錄未提供樣本數、信賴區間或完整 Reward 定義。
