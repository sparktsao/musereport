01

The vertical stack

縱向能力堆疊

The lecture’s central move is to stop treating AI development as a model-shopping exercise. Capability comes from the system around the model.

這堂課的核心轉向：不要把 AI 開發視為「選更大模型」。真正的能力來自模型周圍的系統設計。

Don’t only move sideways.

不要只橫向換模型。

A frozen, stateless predictor gains access, control, and agency as layers are added above it.

基礎模型是凍結、無狀態的預測器；向上加層，才逐步獲得存取、控制與行動能力。

02

Chapter-by-chapter

逐章結構化摘要

Six chapters move from the limits of a raw model to a practical systems-building roadmap.

六個章節從基礎模型的限制，一路推進到可落地的系統建構路線。

0:00

The AI Builder’s learning dilemma

AI Builder 的學習困境

Prompt tricks, fine-tuning, RAG, agents—a pile of disconnected buzzwords with no map. The thesis: learn which pain each technique relieves, not more tools.

Prompt 技巧、Fine-tuning、RAG、Agent 像一堆彼此斷裂的術語。重點不是多學工具，而是理解每種技術解決哪一種痛點。

0:50

Base LLM limits + vertical-axis thinking

LLM 限制與「縱軸思維」

A raw model has a knowledge cutoff, no private-data access, and no durable state. Instead of only comparing bigger and smaller models, stack prompt, retrieval, tool, and workflow layers.

原始模型有知識截止點、無法存取私有資料，也沒有持久狀態。不要只比較模型大小，而要疊加 Prompt、檢索、工具與流程層。

3:30

Three tools that strengthen one LLM

強化單一 LLM 的三大工具

Prompt engineering

Cheapest lever: instructions, roles, zero/few-shot, chain-of-thought, templates, and prompt chains. Evaluate with rubric, pairwise, or reference-guided judges over 100+ cases.

成本最低：清楚指令、角色、zero/few-shot、CoT、模板與 prompt chaining。應用 rubric、成對比較或參考答案，對 100+ 測試案例做評估。

Fine-tuning

Changes weights. Best for tone, format, and stable domain behavior—not fact injection. Risks include catastrophic forgetting, cost, and model-version staleness.

改變權重，適合語氣、格式與穩定領域行為，不適合灌入知識。風險包括災難性遺忘、成本與版本過時。

RAG

The default for missing knowledge: chunk, embed, index; then retrieve top-K and synthesize a grounded answer. Advanced moves include HyDE and reranking.

面對缺失知識的預設解：切塊、向量化、索引，再取 top-K 內容生成有根據的答案；進階可用 HyDE 與 reranking。

11:40

Agentic workflow system design

Agentic Workflow 系統設計

The leap is from answering to doing. A refund workflow retrieves policy, asks for an order number, calls the order API, checks eligibility, and confirms the outcome. Components are prompts, context/memory, and tools. MCP standardizes tool interfaces; autonomy ranges from hard-coded steps to planning agents.

關鍵是從「回答」跨到「執行」。退款流程會檢索政策、詢問訂單編號、呼叫 API、檢查資格並確認結果。核心元件是 Prompt、Context/Memory 與 Tools；MCP 統一工具介面，自主程度則從硬編碼流程延伸到可規劃的 Agent。

17:30

Evaluation + customer-support agent build

評估系統與客服 Agent 實作

Measure end-to-end and component-level performance; separate objective checks from subjective rubric judgments. Decompose support work with domain experts, classify each step as fuzzy (LLM) or deterministic (rules/tools), and preserve traces for debugging.

同時衡量端到端與元件層表現，並區分客觀檢查與主觀 rubric。與領域專家拆解客服工作，把每一步分成模糊型（LLM）或確定型（規則／工具），並保留 trace 以便除錯。

22:15

Multi-agent + learning roadmap

Multi-Agent 與學習路線

Specialization and parallelism justify multi-agent systems; single-turn tasks do not. Start with primitives—prompting, evals, retrieval, tool use, orchestration—rather than chasing frameworks. Future frontiers: architecture search and multimodality.

專業分工與平行處理可支持 Multi-Agent；單輪任務通常不需要。優先掌握 prompting、evals、retrieval、tool use、orchestration 等基本功，而非追逐框架。前沿方向是架構搜尋與多模態。

03

Choose by the pain

依問題選技術

The compact decision framework behind the whole lecture.

整堂課背後最精簡的技術決策框架。

KNOWLEDGE PROBLEM知識問題→ RAG first

Retrieve fresh or private facts; fine-tune last.

先檢索新鮮或私有事實；最後才考慮 fine-tuning。

BEHAVIOR / FORMAT行為／格式問題→ Prompt first

Clarify instructions and examples before changing weights.

改權重前，先把指令與示例說清楚。

MULTI-STEP GOAL多步驟目標→ Agentic workflow

Use no more autonomy than the task requires.

不要使用超過任務所需的自主性。

SPECIALIZATION + PARALLELISM專業化＋平行化→ Multi-agent

Only when decomposition creates real quality or speed gains.

只有拆分確實能帶來品質或速度收益時才採用。

Always:永遠：Build evals before iterating, and keep the traces.迭代前先建立評估，並保留完整 traces。

05

What to retain

真正要帶走的觀念

System > model系統 > 模型

The model is one layer. Retrieval, tools, memory, workflow, and evaluation create usable capability.

模型只是其中一層；檢索、工具、記憶、流程與評估共同構成可用能力。

Trace the failure追蹤失敗位置

In probabilistic software, traces replace the comfort of a conventional step-through debugger.

在機率式軟體裡，trace 取代了傳統逐步除錯器帶來的確定感。

Match complexity to value複雜度要對應價值

Multi-agent is an architecture choice, not a maturity badge. Add it only for real specialization or parallelism.

Multi-Agent 是架構選擇，不是成熟度勳章；只有真實的專業分工或平行需求才值得採用。

Evals are the flywheel評估是成長飛輪

Every production failure should become a permanent test case, tightening the loop between reality and the golden set.

每個 production failure 都應成為永久測試案例，縮短真實流量與 golden set 之間的差距。
