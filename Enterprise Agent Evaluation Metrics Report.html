01 / EXECUTIVE SUMMARY

Evaluation is a release system, not a leaderboard.

The enterprise pattern is deterministic-first scoring, a private versioned gold set, calibrated human and LLM judgments, production feedback loops, and progressive rollout with an already-tested rollback.

Benchmark warning
~100%

scores without solving

UC Berkeley RDI reported exploit agents reaching near-perfect results on major harnesses. Public scores are evidence receipts—not capability certificates.

UC Berkeley RDI summary · Apr 2026 [index-sourced]
Statistical power
95% CI

size to the decision

Choose n from baseline rate, minimum detectable regression, desired power, and critical slices. A 200-case pilot at 90% yields roughly 85–94%—still too wide for a subtle release delta.

Release doctrine
3 axes

quality · p99 · $/task

A release only wins when quality clears its confidence bound without violating tail latency or unit economics.

Core principle

Use the cheapest reliable mechanism for each criterion: schema checks, state assertions, exact matches, budgets, and latency before a judge model; use a judge only where meaning is genuinely open-ended.

03 / METRIC CATALOG

Search the measurement dictionary

Use this as a design checklist. Every release criterion should map to a metric, owner, data source, confidence rule, and response.

Task success rate LLM

successful tasks / attempted tasks

Prefer deterministic state or hidden-test checks; always publish n and confidence interval.

Tool F1 LLM

2 · precision · recall / (precision + recall)

Compares invoked tools with the reference tool multiset; separate selection from argument accuracy.

Step efficiency LLM

min(1, optimal_steps / actual_steps)

Flags loops and waste, but can penalize valid alternative paths; pair with outcome success.

Recovery count LLM

count(error → successful recovery)

Resilience signal; interpret with failure exposure and recovery correctness.

Judge agreement LLM

Cohen κ / Krippendorff α + 95% CI

Chance-corrected agreement; raw agreement is misleading under class imbalance.

Recall@K RAG

relevant retrieved@K / all relevant

The retrieval floor: a missing chunk cannot be used by the generator.

MRR RAG

mean(1 / first_relevant_rank)

Best for single-answer factoid queries; practitioner “good” >0.6, excellent >0.8.

nDCG@K RAG

DCG@K / ideal DCG@K

Rank-aware relevance; practitioner target nDCG@10 >0.8, with classical-IR caveats.

Faithfulness RAG

supported claims / total claims

Groundedness against retrieved context; the critical generation-side RAG signal.

Context precision RAG

rank-weighted relevance of retrieved chunks

Measures retrieval noise; needs gold relevance labels or a calibrated relevance judge.

Citation accuracy RAG

supported citations / citations made

Verifies that cited material really contains the asserted fact.

Regeneration rate USER

sessions with regenerate / eligible sessions

A direct A/B signal: the first answer was poor enough to request another.

Correction rate USER

corrective turns / assistant turns

Narrowly classify “No…”, “I meant…”, and similar corrections as prior-turn failures.

Abandonment USER

early-ended sessions / started sessions

Strong negative signal; segment by task and latency before attributing cause.

Escalation rate USER

human handoffs / eligible sessions

Read with containment and false-resolution rate; low escalation alone can hide wrong answers.

TTFT SCALE

first_token_time − request_arrival

Captures queue and prefill; report p50/p90/p95/p99, never only an average.

TPOT SCALE

(E2E − TTFT) / (output_tokens − 1)

Per-token decode speed; request-weighted. ITL is the token-weighted counterpart.

Goodput SCALE

SLO-met requests / wall time

Useful throughput. Raw tokens/sec can improve while SLO-met economics collapse.

Effective context SCALE

longest length retaining ≥85% base score

Operationalizes long-context decay instead of trusting the advertised window.

Prefix hit rate KV

cached prompt tokens / prompt tokens

Primary reuse metric; real chat references span 40–80%, workload-dependent.

Block utilization KV

used KV blocks / allocated KV blocks

Sustained pool utilization above 90% is a capacity warning in practitioner guidance.

Preemption rate KV

preempted requests / requests

More than 1% indicates problematic memory pressure in cited operating guidance.

KV bytes/request KV

2·L·Hkv·D·S·B·bytes

Capacity model for standard attention; use KV heads, not query heads.

Cost per completion BIZ

total run cost / successful tasks

Includes model, retrieval, tools, retries, and judge cost; pair with SLO compliance.

Cost per SLO-met token BIZ

serving cost / output tokens meeting SLO

Correct denominator for capacity economics; exposes false savings after saturation.

Guardrail trip rate RISK

blocked unsafe runs / evaluated runs

Monitor by severity and attack family; a red-team tool is a bounded signal, not proof of security.

04 / LLM + AGENT

Score the outcome and the path

Binary task success is necessary but not sufficient. Pair it with process quality, safety, cost, and judge validity so “lucky success” cannot pass as robust behavior.

Trajectory score
s_task = s_safe · (0.80·s_comp + 0.20·s_rob)
s_process(t) = g_t · (0.40·e_t + 0.40·i_t + 0.20·v_t)

ClawTrack 2026 formulation. Safety and goal alignment are gates—not additive bonuses. [index-sourced]

Judge contract
  • One narrow dimension per judge
  • Anchored binary or 1–5 rubric
  • Temperature near zero for label
  • Cross-family judge vs candidate
  • Model ID + rubric + prompt hash pinned
  • κ validated against human labels
20–30%

position flips

Reported share of pairwise verdicts that can flip when order swaps. Run both orders and accept only consistent outcomes.

≈15%

verbosity inflation

Reported score lift for longer answers. Add concision as an explicit dimension and use length-controlled win rates.

κ ≥ .6

working judge bar

Substantial agreement is a starting gate. For regulated work, Krippendorff’s α ≥.800 is the stricter “rely on data” convention.

Statistical protocol

Use paired per-case comparisons, 10,000-resample bootstrap or paired tests, repeated stochastic runs, and a predeclared decision rule. Publish score, confidence interval, n, temperature, seed, harness version, and judge contract together.

05 / RAG

Separate retrieval failure from generation failure

Evaluate exact document IDs before judging prose. The retriever must surface evidence; the generator must use it faithfully and cite it accurately.

If context is bad

Fix retrieval

Chunking, embedding model, hybrid BM25+dense, reranker, metadata filters, top-K, query rewrite, and authorization filters.

If context is good

Fix generation

Grounding prompt, citations, abstention, lower temperature, constrained output, and a claim-level faithfulness gate.

If context is ignored

Fix context shape

Shorten or reorder evidence, test lost-in-the-middle, and inspect agentic retrieve→reason→re-retrieve loops.

Golden retrieval dataset

  • Start with a 200–500 case working set, then power the release decision and critical slices explicitly
  • Query, relevant chunk/document IDs, ideal answer, query-type tag
  • Human-authored + anonymized production + deterministic DB questions
  • Hard negatives, ambiguous, multi-hop, freshness, and ACL cases
  • 10–20% genuinely unanswerable
  • Two human reviewers per reference; versioned with the code
  • Every production incident becomes a regression case

Tool stack by job

CI: Ragas or DeepEval. DeepEval is pytest-native and includes agentic metrics.

Production tracing: TruLens and OpenTelemetry-oriented platforms.

Defense in depth: dedicated hallucination detection on top.

2026 practitioner consensus. LangChain’s load_evaluator is described as legacy/frozen; ARES showed limited activity since Mar 2025.

06 / USER FEEDBACK

Behavior is the honest online label

Thumbs and surveys are sparse and selection-biased. Treat retries, corrections, abandonment, escalation, and downstream completion as a richer—though still confounded—signal layer.

Strong negative signals

  • Early termination
  • Error correction
  • Regeneration request
  • Repeated reformulation
  • Escalation to human

Positive signals

  • Verified task completion
  • Accepted downstream action
  • Resolved session without retry
  • Retention / successful reuse
  • Explicit positive rating

Bias controls

  • Uniform production sampling
  • Stratify by tenant and task
  • Separate latency from quality
  • Human-review high-risk traces
  • Disclose behavioral analysis

The feedback-to-eval flywheel

01Capture

Explicit dislike or behavioral flag

02Triage

Route representative trace to review

03Root-cause

Domain expert identifies failure

04Augment

Add corrected case and variations

05Regress

Run on every future candidate

Production SLI

Sample roughly 5% of daily sessions for asynchronous rubric grading, aggregate over rolling windows, and use confidence bands or change-point detection. A fall in eval pass rate is a reliability incident—not merely “model feedback.”

07 / TIME + SCALE

Tail latency and goodput reveal the real system

Separate queue/prefill from decode, report percentiles, and denominator economics on requests that meet the SLO. Raw throughput can improve while useful capacity collapses.

TTFT = request arrival → first token
TPOT = (E2E − TTFT) / (output tokens − 1)
E2E = TTFT + TPOT · (tokens − 1)
Throughput = output tokens / wall time
Goodput = SLO-met requests / wall time

Report every run with

  • p50 / p90 / p95 / p99
  • min / max / standard deviation
  • Prompt and output lengths
  • Concurrency and arrival pattern
  • Hardware, precision, batch policy

Long-context and long-horizon tests

Context-length decay

Measure accuracy at multiple placements and lengths. “Lost in the Middle” found >30% drops in some settings; RULER work suggests effective context can be 50–65% of nominal. Adopt effective length = longest context retaining ≥85% of base score.

Step-count decay

Hold context length approximately constant while increasing tool turns. Step-driven degradation can be distinct from context-length degradation; do not assume compaction fixes it. Track loops, repeated failures, and rereads.

Progressive release gate

08 / KV CACHE

Cache quality is correctness plus economics

Track not only hit rate, but memory footprint, preemption, locality, tail latency, and invalidation correctness across weights, adapters, tenants, tensor-parallel shards, and compaction.

Footprint formula
KV bytes = 2 × layers × kv_heads × head_dim × sequence × batch × bytes/element

The factor 2 is K and V. Use KV heads—not query heads. For MLA, substitute latent width and drop the leading 2.

Worked capacity anchors

Generic 32L / 32-head FP16: ≈0.5 MB per token; a 4K request ≈2 GB.

Llama 3.1 70B GQA: ≈0.33 MB per token; 128K context ≈40 GB for one user.

Architectural estimates from cited 2026 KV engineering notes.

40–80%

chat prefix-hit range

Workload-dependent practitioner reference. Prefix-heavy systems report higher, but those results are not portable.

<1%

preemption guide

Above 1% of requests is considered a problem in cited operating guidance.

<90%

sustained KV pool

Sustained utilization above 90% is a warning to add capacity or change policy.

Correctness tests

  • Weight hash change creates a miss
  • Adapter identity is included in key
  • Tenant salt prevents cross-tenant reuse
  • Referenced blocks cannot be evicted
  • TP shards evict coherently
  • Compaction invalidates expected prefixes

Locality and routing tests

  • Stable system prompt appears first
  • User-specific and timestamp data moved later
  • Cache-aware router beats round-robin
  • Shared cache benefit exceeds transfer tax
  • PCIe-only topology tested against replicas
  • TTFT improvement holds at p99
Economic top line

Report cost per SLO-met output token. In one L40S/Qwen3-8B study, 80% prefix reuse moved the figure from $1.18 to $0.39 per million SLO-met output tokens and supported 12→32 seats; treat this as a workload-specific measured anchor.

09 / ENTERPRISE SYSTEM

Bind quality, safety, cost, and auditability

The release artifact is not just a score. It is a reproducible contract: inputs, versions, uncertainty, owners, approval, and a tested response when production diverges.

Security

Adversarial release gate

Threat model → attack library → fuzz/mutate → execute → deterministic + judge scoring → severity ranking → patch → retest.

PyRIT, DeepTeam/DeepEval, and Garak cover many attack families; none proves the full system secure.

Reproducibility

Immutable evaluation receipt

Model ID, agent graph, prompt hash, data hash, temperature/seed, tool versions, judge contract, timestamps, human sign-offs, CI, and rollout decision.

Economics

Pareto release frontier

Compare only non-dominated quality–latency–cost points. Measure $/task, tokens/task, $/successful SLO-met task, GPU/MFU, and retries.

10 / 90-DAY PLAN

Stand up the system in three phases

The goal is not a giant metric catalog on day one. It is a trustworthy minimum gate that compounds: every incident improves the suite.

DAYS 1–30

Instrument + baseline

  • Define risk tiers and SLOs
  • Create private gold set
  • Wire deterministic outcome checks
  • Baseline success, tool F1, cost, TTFT/TPOT
  • Calibrate judge and annotators
DAYS 31–60

Harden + stress

  • RAG retrieval and faithfulness gates
  • Adversarial and authorization cases
  • Load, context-length, and step-decay sweeps
  • KV locality / invalidation tests
  • Test rollback path
DAYS 61–90

Operate + learn

  • CI regression gate
  • Shadow and risk-stratified canary
  • Feedback triage and annotation queue
  • Weekly failure review
  • Every incident → regression case
